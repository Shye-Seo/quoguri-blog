11월 17일 GPT-6.2가 나왔다는 소식을 보고, 18일에는 Gemini 4 Neon 기사가 올라왔어요. 하루 만에 "1위"가 바뀌는 걸 보면 뉴스를 다 읽어야 하나 싶어요. 그런데 막상 며칠 지나서 내 계정을 열어 보면, 새 모델은 안 보이고 쓰던 모델만 그대로예요.

그래서 저는 새 모델 소식이 나오면 **순서를 정해서** 봐요. 이 글은 그 순서를 11월 실제 사례로 연습해 보는 글입니다.

## 1. '출시'라는 말부터 의심한다

같은 "나왔다"라도 상태가 네 가지로 달라요.

| 상태 | 뜻 | 11월 사례 |
| --- | --- | --- |
| 발표 | 회사가 존재를 알림. 아직 못 쓸 수 있음 | Gemini 4 Argon 9월 30일 발표 → 10월 13일 일반 공개 |
| 미리보기 | 일부 계정에만 열림 | Gemini 3.1 Pro 프리뷰 |
| 일반 공개 | 요금제·API에서 바로 사용 가능 | GPT-6.2 Astra·Sol (11월 17일 API) |
| 제한 공개 | 검증·승인받은 고객만 | Mythos 5.2, GPT-6 Cyber, Carbon 사이버 특화판 |

이걸 구분하지 않으면 "최고 성능 모델이 나왔다"는 기사를 보고 결제했는데 내 요금제에서는 안 보이는 일이 생겨요. 실제로 Gemini 4 Carbon은 10월 28일 발표됐지만, 유료 개발자·기업에 일반 공개된 건 11월 10일이고요. 그것도 "일부 지역의 검증된 기업 고객"이 대상이라고 회사가 밝혔어요.

**확인 순서는 간단해요.** 회사 발표문에서 ① 지금 쓸 수 있는지 ② 어디서 쓸 수 있는지(앱·API·클라우드) ③ 내 요금제에 포함인지. 이 세 줄만 찾으면 돼요.

## 2. 자체 발표 숫자와 외부 측정을 나눠 본다

회사가 발표하는 점수는 대개 **회사가 유리한 설정**에서 잰 값이에요. 이게 틀렸다는 뜻은 아니고, 조건을 같이 읽어야 한다는 뜻이에요.

좋은 예가 Claude Opus 5.5의 터미널 작업 점수예요. Anthropic 자체 발표는 66.4%였는데, 같은 평가를 외부 기관이 잰 값은 60%였어요. 6%p 차이면 순위가 바뀔 수 있는 크기예요. 반대로 외부 지수에서 1위를 찍은 모델도, 그 1위가 **어떤 설정에서 나온 값인지**를 봐야 해요.

- Fable 5.2의 64.6점은 **max 설정**, 과제당 비용 $26.54
- high 설정은 61.8점, 과제당 $9.08
- GPT-6.2 Astra는 max 62.1점 $4.00, high 60.1점 $2.07

"1위"와 "내가 쓸 설정"이 다를 수 있다는 것, 이게 뉴스에서 제일 많이 빠지는 부분이에요.

## 3. 새 모델보다 '내가 쓰던 모델'의 일정을 본다

솔직히 저한테는 이게 제일 중요해요. 새 모델이 아무리 좋아도, 내가 쓰던 모델이 비싸지거나 사라지면 바로 문제가 되니까요. 11월 말에 걸린 일정만 모아 봤어요.

| 날짜 | 바뀌는 것 | 나에게 생기는 일 |
| --- | --- | --- |
| 11월 30일 | Gemini 4 Carbon·Argon 도입가 종료 | 12월 1일부터 단가 2배($2/$10 → $4/$20) |
| 11월 30일 | Claude Sonnet 4.5 API 퇴역 | 자동화에 물려 있으면 코드 수정 필요 |
| 12월 3일 | Gemini Omni 1.1 요청이 1.2로 자동 전환 | 결과물이 달라질 수 있음 |

그리고 하나 더. GPT-6 Astra와 GPT-6.1 Sol은 Artificial Analysis 리더보드에서 '이전 모델'로 분류돼서 표에서 빠졌어요. 그런데 **서비스가 끝난 건 아니에요.** Amazon Bedrock에서는 계속 제공돼요. 리더보드에서 사라진 것과 서비스 종료는 완전히 다른 이야기예요.

## 4. 내 작업 3개로 30분만 테스트한다

뉴스를 다 읽는 것보다 이게 빨라요. 새 모델이 내 계정에 열렸다면, 평소 하던 작업 세 개를 그대로 넣어 봐요.

- **요약**: 3,000자짜리 기사 하나를 "3줄 요약 + 내가 답할 질문 3개"로
- **작성**: 실제로 보낼 메일 답장 하나 (내 말투 조건 포함)
- **수정**: 기존 코드나 문서 한 조각을 "내용은 그대로, 형식만" 고치기

채점은 세 가지만 봐요.

| 보는 것 | 어떻게 세나 |
| --- | --- |
| 사실 오류 | 틀린 숫자·날짜·링크 개수 (0이 목표) |
| 형식 준수 | 시킨 형식에서 벗어난 항목 수 |
| 수정 횟수 | 내가 손본 문장 수 |

같은 프롬프트를 기존 모델과 새 모델에 똑같이 넣고, 위 세 숫자만 비교하면 30분이면 끝나요. 점수표보다 이 표가 내게는 더 정확해요.

## 마무리

정리하면 이 순서예요.

1. **출시 상태** 확인 (발표 / 미리보기 / 일반 공개 / 제한 공개)
2. **설정과 비용**을 같이 읽기 (max인지 high인지, 과제당 비용은 얼마인지)
3. **내가 쓰던 모델의 단가·퇴역 일정** 확인
4. **내 작업 3개로 30분 테스트**

뉴스는 재료고, 결정은 테스트로 하는 거예요. 11월처럼 새 모델이 쏟아지는 달에는 이 순서가 없으면 하루 종일 기사만 읽다가 끝나요.
